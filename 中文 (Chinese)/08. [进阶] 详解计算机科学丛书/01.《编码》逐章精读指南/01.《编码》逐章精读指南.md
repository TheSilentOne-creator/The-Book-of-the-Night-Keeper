## 第1章：至亲密友

**核心内容**：两个小孩隔着窗户，用手电筒发信号。灯亮是1，灯灭是0。这就是二进制编码的起点。

**你的笔记：**

- **手绘**：两个房子之间，画一条虚线表示视线。左边小孩手里一支手电筒，右边小孩眼睛看向它。
- **写一句话**：“信息不需要声音，只需要一个能被双方共同解释的状态变化。”
- **白皮书映射**：你的 `broadcast` 指令，本质上就是向多个 EU 发出同一个“闪光”。只是这次，闪光的意思不是字母，是 `AddOne`。

## 第2章：编码与组合

**核心内容**：用多个手电筒（多个比特）可以表示更多信息。从1个比特的2种状态，到2个比特的4种状态，到3个比特的8种状态。

**你的笔记：**

- **画表格**：画出2比特的四种组合（00 01 10 11），标注每种组合代表的字母。
- **写一句话**：“信息量随比特数指数增长——这是未来所有并行计算的信息论基础。”
- **白皮书映射**：你的 `[i32; 1_000_000]` 数据类型——每个 `i32` 就是 32 支手电筒。你广播一次任务，就是同时对 3200 万支手电筒说：“全体注意，按这个规则改变你们的明灭状态。”

## 第3章：布莱叶盲文与二进制码

**核心内容**：盲文用6个点表示字母。这是一种**物理上凸起的编码系统**，不依赖声音或视觉。

**你的笔记：**

- **手绘**：画一个 2×3 的点阵，涂黑其中几个点，标注对应的字母。
- **写一句话**：“编码的本质，是用最小的物理状态变化，承载最大的语义信息。”
- **白皮书映射**：这是你的 `task` 为什么要设计为纯函数的哲学源头——任务只需要“输入状态”和“输出状态”，中间的物理过程对指挥官完全透明。盲人不需要看手电筒的光，计算机不需要看电流的颜色。

## 第4章：手电筒的剖析

**核心内容**：把手电筒拆开，讲电池、导线、开关、灯泡。这是**电路**的起点。

**你的笔记：**

- **手绘**：画一个完整的电路图。电池（长线和短线），开关（断开的），灯泡（圆圈里一个X）。标注电流方向。
- **写一句话**：“电路是一个闭环。电流从电池正极出发，必须回到负极，途中经过的所有元件都会受到影响。”
- **白皮书映射**：这是“统一地址空间”的物理原型。电流不关心它经过了哪个元件，就像你的 `broadcast` 不关心数据在哪个核心上跑——它只需要一个闭环，数据从内存出发，经过 EU，回到内存。闭环必须完整。

## 第5章：绕过拐角的通信

**核心内容**：导线不够长怎么办？加长导线。信号要绕过拐角怎么办？用更长的导线。**距离**是通信的第一个敌人。

**你的笔记：**

- **手绘**：画一栋房子的俯视图，导线从一楼沿墙角蜿蜒到二楼。
- **写一句话**：“信号衰减是物理定律。距离越远，需要的能量越大。这是所有通信系统必须面对的成本。”
- **白皮书映射**：你的 `broadcast` 在异构计算中，CPU 和 GPU 之间的数据移动，本质上就是“绕过拐角的导线”。编译器需要自动决定：哪些数据放在 CPU 内存，哪些推到 GPU 显存——这是“绕过拐角”在计算机里的等价操作。

## 第6章：电报机与继电器

**核心内容**：电报机用一根导线穿越整个大陆，用长短信号（摩尔斯电码）通信。**继电器**是电报机的心脏——它用电磁铁吸引衔铁，实现“用电流控制电流”。

**你的笔记：**

- **手绘（极其重要）**：画继电器的内部结构。线圈绕在铁芯上，旁边是一块衔铁。线圈通电时，衔铁被吸过来。衔铁上连着触点，触点控制另一条电路。
- **旁边用红笔写**：“继电器 = 电流控制的开关。输入是电流的有无，输出是另一条电路的通断。这是**信号放大**和**逻辑门**的物理基础。”
- **白皮书映射**：你的 `broadcast` 被编译器展开为原生指令后，这些指令就是靠数十亿个微型继电器（晶体管）来执行的。每一个 EU，本质上就是一堆能以每秒数十亿次速度通断的继电器。你在第17章会重新见到它。

## 第7章：我们的十个数字

**核心内容**：人类为什么用十进制？因为我们有十个手指。玛雅人用二十进制（加上脚趾）。数学本身不偏爱任何进制。

**你的笔记：**

- **不做电路图**，这章是数学史。
- **写一句话**：“十进制是人类身体的偶然。二进制是逻辑的必然。”
- **白皮书映射**：你的语言选择 `i32`、`f64` 这些类型，本质上是把十进制的“人类意图”和计算机内部二进制的“物理实现”隔离开来。程序员用十进制思考，机器用二进制执行。这是“意图高于算法”的数学根源。

## 第8章：十的替代品

**核心内容**：八进制、四进制、二进制。重点讲二进制如何用0和1表示所有数字。二进制是“最简单的进制”，只需要两个符号。

**你的笔记：**

- **画表格**：0到15的二进制、八进制、十进制、十六进制对照表。
- **写一句话**：“二进制是开关的自然语言。任何进制之间的转换，都是等价的数学运算。”
- **白皮书映射**：你的 `broadcast` 指令中的数字，最终全部被编译器翻译为二进制。这章是你理解“计算机如何看到你写的数字”的起点。

## 第9章：二进制数的奥秘

**核心内容**：二进制加减法。进位、借位。二进制乘法。逻辑运算的雏形。

**你的笔记：**

- **手算几道题**：用纸笔做二进制加减法。不要用计算器。手算的过程，就是你理解“全加器”如何工作的过程。
- **写一句话**：“二进制加法，就是按位异或（加）加上进位与（进位）。这决定了加法器的物理结构。”
- **白皮书映射**：你的 `task AddOne(x: i32) -> i32 { x + 1 }`——这一行代码，在底层就是这个章节的所有二进制加法规则，被晶体管实现为一条单周期的机器指令。你写的 `+`，是数十亿个继电器精密配合的结果。

## 第10章：逻辑与开关

**核心内容**：将布尔代数（与、或、非）和电路联系起来。串联开关是和，并联开关是或。这是**逻辑门**的物理实现。

**你的笔记（极其重要，必须手绘）：**

- **与门**：两个开关串联。只有两个都闭合，灯泡才亮。画电路图。
- **或门**：两个开关并联。任一个闭合，灯泡就亮。画电路图。
- **非门**：一个常闭继电器。输入通电时，衔铁吸过来，输出断开。画电路图。这是最难理解的——它是“信号翻转”的物理原点。
- **写一句话**：“开关的串联、并联、反接，就是所有逻辑运算的物理基础。把这三个基础电路无限组合，就能造出计算机。”
- **白皮书映射**：你的 `task` 中所有的算术逻辑（`+`、`-`、`*`、`/`、`&&`、`||`），最终都分解为这三个基本逻辑门。你写的每一条 `broadcast` 指令，最终都是由这些门电路组合而成的机器指令序列。

## 第11章：门

**核心内容**：把上一章的与或非门标准化。引入符号（与门是D形，或门是弧形，非门是三角形加小圆圈）。**门是逻辑的最小封装单元。**

**你的笔记：**

- **画标准符号表**：与门、或门、非门、与非门、或非门的符号和真值表。
- **写一句话**：“门，把一堆继电器封装成一个逻辑功能。这就是抽象的第一层——你不再需要关心继电器怎么吸合，只需要知道这个门的输入输出关系。”
- **白皮书映射**：这就是你的 `task` 为什么是纯函数——函数，就是软件的“门”。你只关心输入输出，不关心里面的继电器（指令）。`task AddOne(x: i32) -> i32` 就是一个“软件与门”：输入 x，输出 x+1。里面的逻辑对调用者透明。

## 第12章：二进制加法器

**核心内容**：用逻辑门组合出半加器（加两个比特，输出和与进位），再用半加器组合出全加器（加三个比特——两个输入加进位输入）。把八个全加器串起来，就能做8位二进制加法。

**你的笔记（全程手绘）：**

- **半加器**：异或门 + 与门。画电路图，标注输入（A、B）和输出（Sum、Carry Out）。
- **全加器**：两个半加器 + 一个或门。画电路图，标注输入（A、B、Carry In）和输出（Sum、Carry Out）。
- **8位加法器**：一排八个全加器串联，进位从低位传递到高位。画方块图。
- **写一句话**：“加法器是计算机的‘第一块肌肉’。它让我写的 `x + 1` 不再是一个数学符号，而是一条物理电路。”
- **白皮书映射**：你的 `task AddOne(x: i32) -> i32 { x + 1 }` 中的 `+`，在硬件上就是这一排全加器。编译器把 `+` 翻译为 `ADD` 机器指令，CPU 执行这条指令时，电流流过这排全加器，最后在寄存器里出现结果。这就是你的“零成本抽象”的物理真相。

## 第13章：如何实现减法

**核心内容**：计算机不直接做减法。它用补码——把减数取反加一，然后用加法器加它。这样，加法器既能做加法也能做减法。

**你的笔记：**

- **手算补码**：用纸笔把一个数取反加一，验证负数的二进制表示。
- **写一句话**：“减法 = 补码 + 加法。计算机只需要一种运算器（加法器），用数学技巧覆盖所有运算。”
- **白皮书映射**：这是“意图高于算法”在硬件上的体现。程序员只需写 `x - 1`，编译器负责把它变成补码加1。你只管意图，硬件和编译器共同完成算法。

## 第14章：反馈与触发器

**核心内容**：把逻辑门的输出接回输入端——这就产生了**记忆**。触发器（flip-flop）能存储1个比特。这是**存储器**的起点。

**你的笔记（极其重要）：**

- **手绘RS触发器**：两个或非门互相连接。画清楚S、R输入端和Q、Q̄输出端。用不同颜色的笔标注“置位”（S=1，Q变成1）和“复位”（R=1，Q变成0）时的电流走向。
- **写一句话**：“记忆的秘密不是材料，是结构。电流在环里循环，就能‘记住’刚才发生了什么。”
- **白皮书映射**：你的 `let data: [i32; 1_000_000] = [1, 2, 3, ...]`，这一百万个数字，就存储在一百万个触发器阵列里。你的“统一地址空间”，物理上就是由几十亿个这种触发器构成的 RAM。读这一章时，你会第一次亲眼看到，内存里的一个字节，到底长什么样。

## 第15章：字节与十六进制

**核心内容**：8个比特 = 1个字节。十六进制是二进制的缩写——4个比特正好对应1个十六进制位。内存地址用十六进制表示。

**你的笔记：**

- **画对照表**：二进制（4位）、十六进制（1位）、十进制对照。
- **写一句话**：“字节是计算机存储的最小可寻址单位。十六进制是程序员的二进制速记法。”
- **白皮书映射**：你白皮书里的 `[u8; 256]` 类型——`u8` 就是1字节。读到这里，你会知道这个 `8` 不是随便选的，它是触发器物理结构的直接映射。

## 第16章：存储器组织

**核心内容**：如何把大量触发器组织成可寻址的存储器阵列。地址译码器——输入一个地址（几根线），选中对应的存储单元（一行触发器）。RAM的结构：地址线、数据线、读写线。

**你的笔记：**

- **画方块图**：不用画每个触发器。画一个格子阵列，行是地址，列是数据位。外面连着三条总线：地址总线、数据总线、控制总线（读/写）。
- **写一句话**：“存储器 = 触发器阵列 + 地址译码器。给定一个地址，就能读写这个地址上的数据。这就是‘指针’的物理实现。”
- **白皮书映射**：你的“统一地址空间”，在物理上就是这张方块图放大到几十亿个存储单元。`TO ALL CPU_CORES` 广播时，每个核心通过自己的地址总线，访问同一块物理内存的不同区域——这就是你白皮书里“统一地址空间”这四个字的全部物理含义。

## 第17章：自动操作

**核心内容**：把前面造的所有东西——ALU、存储器、触发器——拼在一起，加上一个**控制单元**。控制单元读取指令，指挥ALU运算，指挥存储器读写。这就是**冯·诺依曼架构**。

**你的笔记（全程手绘，这是整本书的总装图）：**

- **画冯·诺依曼架构图**：
- 左上：CPU（里面再拆成控制单元和ALU）
- 右上：存储器（指令和数据混存）
- 下面：输入设备和输出设备
- 用箭头标出：地址总线、数据总线、控制总线
- **在旁边用红笔标注每个部件和你的白皮书的对应关系**：
- “控制单元” → `broadcast` 指令的调度逻辑
- “ALU” → `task` 函数体的执行硬件
- “存储器” → `统一地址空间`
- “输入输出” → `TO CONSOLE` / 传感器 / 网络
- **写一句话**：“冯·诺依曼架构的本质：指令和数据放在同一块内存里，CPU按顺序取指令、解码、执行。这是过去八十年所有通用计算机的祖宗。”
- **白皮书映射**：你的 BroadCaster 编译器，最终生成的机器码，就运行在这个架构上。你写的 `broadcast` 会被翻译成一串机器指令，CPU 的控制单元一条条取走，指挥 ALU 和内存协同工作。

## 第18章：从算盘到芯片

**核心内容**：历史回顾——机械计算器→机电计算器→电子管→晶体管→集成电路→微处理器。摩尔定律。

**你的笔记：**

- **不做电路图**。画一条时间轴，标注每个时代的代表机器和核心元件。
- **写一句话**：“继电器（开关）→ 晶体管（更快的开关）→ 集成电路（把开关刻在硅片上）→ 微处理器（把整个冯·诺依曼架构刻在一片硅片上）。所有进步，本质上是开关速度变快、体积变小、功耗变低。”
- **白皮书映射**：你现在写的 `broadcast`，就是在指挥一片指甲盖大小的硅片上，刻着的几十亿个晶体管。而这些晶体管的工作原理，和查尔斯·巴贝奇的分析机里的黄铜齿轮，在逻辑上是完全一样的。这，就是“底层”二字的历史厚度。

## 第19章：两种典型的微处理器

**核心内容**：Intel 8080（8位）和 Motorola 6800（8位）的比较。寄存器、指令集、寻址模式。这是现代CPU的直系祖先。

**你的笔记：**

- **画8080的寄存器图**：累加器A、通用寄存器B/C/D/E、堆栈指针SP、程序计数器PC。标注每个寄存器的作用。
- **写一句话**：“寄存器是CPU的手。CPU不直接操作内存，它把数据从内存搬到寄存器，在寄存器里操作，再搬回内存。”
- **白皮书映射**：你的 `task` 里的每一个变量，在运行时都会被分配到寄存器或内存。编译器负责这个分配——它是你的“自动调度员”。你不需要手动管理寄存器，因为 BroadCaster 和它的编译器会帮你做这件事。这是“意图高于算法”在寄存器层面的体现。

## 第20章：ASCII码及其他

**核心内容**：如何用数字表示字母。ASCII用7位表示128个字符，扩展ASCII用8位。Unicode的前身。

**你的笔记：**

- **画一个简化ASCII表**，只记关键字符的码点：`'A'=65`，`'a'=97`，`'0'=48`，空格=32，换行=10。

## 第21章：总线

**核心内容**：计算机内部各部件如何通信。地址总线（单向）、数据总线（双向）、控制总线。总线带宽决定系统吞吐量。

**你的笔记：**

- **画三总线示意图**：CPU、RAM、外设（键盘、屏幕、磁盘）都挂在三条总线上。标注每条总线的方向和功能。
- **写一句话**：“总线是计算机内部的‘广播系统’。CPU在地址总线上喊一个地址，所有设备都听见，但只有对应那个地址的设备会回应。”
- **白皮书映射**：这，就是“广播”在物理层面的原生实现。你的 `broadcast` 语法，不过是在软件层面给这套已经存在了几十年的硬件通信机制，起了一个人类可读的名字。总线，就是硬件的广播原语。
