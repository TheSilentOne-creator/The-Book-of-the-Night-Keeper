## 第一章 - 初识 Git & GitHub

---

### 1.x Git 是如何实现版本管理的

前面讲了那这么，那么守夜者，你有没有好奇过 Git 是 **如何实现版本管理** 的呢？

这个问题问得很有档次。不讲代码，我们讲思想。

Git的版本管理，本质上不是"帮你存了每个版本的文件"，而是**用最低的成本，给整个项目的每次快照建立了一套"时空穿越"的档案系统。**

---

**核心思想：快照，而不是差异**  

绝大多数版本管理系统（比如SVN）的思维是：**记录文件每次改了什么**。就像记账：

> 版本1：有A、B、C三个文件  
> 版本2：A文件第3行加了xxx，B文件删了  
> 版本3：C文件改了yyy

Git不这么干。Git的思维是：**每次提交，直接给整个项目拍一张"全家福"。**

你没看错，是**整个项目**。所有文件的当前状态，咔嚓一下，全存下来。

这时候你肯定想：这不得把硬盘撑爆？

这就是Git最精妙的地方。

---

**文件的"身份证"：SHA-1哈希值**  

Git不给文件起名字，它给每个文件的内容计算一个**40位的十六进制字符串**，叫SHA-1哈希值。比如：

```text
e69de29bb2d1d6434b8b29ae775ad8c2e48c5391
```

这个哈希值有两个恐怖的性质：

1. **唯一性：** 同样的内容，永远算出同一个哈希值；内容哪怕改了一个bit，哈希值就面目全非。
2. **不可逆：** 从哈希值反推不出内容。

于是，**这个哈希值，就成了文件内容的"指纹"。**

---

**怎么存？—— "只要指纹没变，就不用再存一遍"**  

当你提交一个新版本时，Git会遍历项目里所有文件：

- **对于内容没变的文件：** 它的哈希值跟上一个版本一样。Git说："这个文件我仓库里已经有了，不用再存了，记个指针就行。"

- **对于内容变了的文件：** 计算新的哈希值，把新内容存进去。

所以，你看起来Git给每个版本都拍了"整个项目的快照"，实际上，**那些没变动的文件，只是在新快照里记了个引用，并没有占用新的存储空间。**

这就像你每年拍一张全家福。照片上的人，今年和去年长得一样，就不用重新"制造"这个人，在照片上标注"还是去年那个人"就行。只有变了的人，才需要更新。

---

**那版本本身长什么样？—— 提交对象**  

每个版本（每一次`commit`），Git都会创建一个**提交对象**，里面记录了：

- 这个版本的项目快照：是一个树结构，记录了项目里所有文件/文件夹的哈希值。

- 作者和时间：谁在什么时候提交的。

- 提交说明：你写的commit message。

- 父提交的指针：关键！它指向了**上一个版本是哪个提交对象**。

这个"指向父提交"的设计，让所有版本串联成了一条**链条**。

---

**于是，Git的历史变成了一个"链表"**  

```txt
A → B → C → D
↑   ↑   ↑   ↑
v1  v2  v3  v4
```

每个节点都是完整项目的快照（通过哈希去重）。你想回到B版本？Git只需要找到B这个提交对象，然后根据它记录的文件哈希值，把所有文件还原出来。

这就是**时空穿越**的本质。不是"撤销"了改动，而是重新"播放"了那个瞬间的一切。

---

**分支：只是一个"会移动的指针"**  

你没看错，分支就是这么简单。

Git里有一个特殊指针叫`HEAD`，它指向你当前在哪个分支。而一个分支名（比如`main`、`dev`），本质上就是一个**指向某个提交对象的指针。**

当你新建一个分支并提交时：

- Git创建一个新的提交对象，它的父提交是你当时的那个版本。
- 然后把分支指针移到这个新提交上。

两个分支共享着相同的"历史基础"，只是因为指针指向了不同的提交，就可以各自往下生长。

---

**合并为什么通常很轻松？**  

因为Git的合并，不是比对你的文件和我文件"哪里不一样"。而是：

> **找到两个分支的"共同祖先"，然后看：**  
> "从祖先到我，改了这些文件。"  
> "从祖先到你，改了这些文件。"  
>
> ——如果我们改的是不同文件，或者同一个文件的不同位置，Git直接自动合并。只有我们改了同一个文件的同一行，Git才会说："我搞不定了，你来吧。"（这就是"冲突"）。

---

**总结：Git的版本管理，是一套"基于内容寻址的文件系统"**  

它不是给文件编号，不是存差异，而是：

> **用内容的哈希值作为索引，构建了一个"只要没变，就不用重存"的智能档案库。然后用链表组织版本，用指针管理分支。**  

所以，Git的仓库为什么这么"瘦"？因为它**几乎不存重复的东西**。为什么可以随便建分支？因为**分支只是一个指针，几乎是零成本**。为什么可以飞速穿梭历史？因为它还原一个版本，就是把那个时刻的"文件指纹"指过去——瞬间完成。

你所有的代码、回滚、分支、合并，背后都是这套优雅的、基于哈希的"时空档案系统"在默默运转。

从这个角度看，Git与其说是一个版本管理工具，不如说是一座用哈希值建造的"时间博物馆"。每一个commit，都是那个时刻你项目的完美复制品，静静地躺在馆里，等待你随时穿越回去。
