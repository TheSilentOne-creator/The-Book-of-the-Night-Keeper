## 前言

### 这本教程是给谁看的？

你是不是也觉得，Vim 是那种“人人都说好，但人人都没用明白”的东西？

你身边可能也有这样的朋友：兴致勃勃装上 Vim，练了两天，放弃了。说“太反人类了”。或者在服务器上不小心进了 Vim，死活退不出来，最后只能关掉终端重开。网上搜了一堆“Vim 速成教程”，学完只会 `i` 和 `:wq`，感觉跟记事本没区别。

你可能就是那个朋友。也可能你正在成为那个朋友的路上——然后你翻开了这本教程。

**这本教程不追求“精通”，只追求“得体”。**

什么叫“得体”？

- 打开 Vim 不慌张，知道自己在什么模式
- 能流畅地移动光标、编辑文本、保存退出
- 手指开始习惯主键盘区，不再依赖方向键
- 写代码时不再觉得“Vim 在拖我后腿”

读完这十节课，你就能做到这些。剩下的，是时间和练习的事。

---

### 这本教程不是什么？

**不是《Vim 实用技巧》的替代品。** 那本书是真正的“绝世武功”，但它的符号表示法（`<C-x>`、`>G` 之类的）会劝退零基础读者。这本教程是你的“新手村任务指南”——读完它，你才有资格翻开那本书。

**不是命令大全。** 我只讲 **80% 的场景下会用到的 20% 的命令**。剩下的，等你真的需要了，自己去查 `:help`。

**不是插件配置教程。** 在学会基础操作之前，别碰插件。插件是给懂 Vim 的人用的，不是给新手用的。

## 第一部分：守夜者的十节课（必修）

> **目标**：让你能“得体”地用 VIM 写代码、改配置、活着退出来。  
> **读完这一部分，你已经超越了 80% 的 VIM 初学者。**

### 第一课：VIM 的第一印象——它的故事与你的第一次握手

---

#### 1.1 Vim 是什么？

Vim 是一个在终端里运行的文本编辑器。

和你在《玩转 VS Code》里用过的编辑器不同：

- Vim 没有鼠标
- Vim 没有菜单栏
- Vim 没有可以点的图标
- Vim 只有键盘

听起来很麻烦。但 Vim 有一个特点：**你的手指不用离开键盘**。所有操作都在主键盘区完成。习惯了之后，你写东西的速度会比用鼠标快很多。

你在 01 教程里学会了用 Markdown 写笔记，在 02 教程里学会了用 VS Code 高效写作。现在，你要接触一个和 VS Code 完全不同的编辑器——它没有图形界面，没有插件商店，没有“设置”按钮。但它有一个 VS Code 永远无法替代的能力：**在任何一台服务器上，它都已经在那里等着你了。**

---

#### 1.2 一个“山寨货”的逆袭

1976 年，一个叫 Bill Joy 的程序员写了一款编辑器，叫 **Vi**。Vi 很强大，但它不是免费的。

1988 年，一个叫 **Bram Moolenaar** 的荷兰程序员决定：既然用不了 Vi，那我自己写一个“高仿版”。他给项目起名叫 **Vi IMitation**（模仿品），缩写就是 **Vim**。

后来 Vim 的功能超过了 Vi，名字也改了——**Vi IMproved**（改良版）。

**小结**：Vim 从一个“山寨货”逆袭成了行业标杆。别怕从模仿开始，Vim 也是这样走过来的。

---

#### 1.3 为什么用 `hjkl` 移动光标？

Vim 里用 `h` `j` `k` `l` 代替方向键。你可能会问：“为什么不用方向键？”

看下面这张图。这是 Bill Joy 当年用的机器（ADM-3A）的键盘：

![ADM-3A_-_animation](<Images/Chapter 1/1.3/ADM-3A_-_animation.png>)

仔细看 `H`、`J`、`K`、`L` 这四个键——上面印着方向箭头。

当时独立方向键在键盘右边，离主键盘区很远。每移动一次光标，手都要整个挪过去。Bill Joy 干脆直接用这四个字母当方向键，手指不用离开主键盘区。

后来他把这个习惯写进了 Vi 的代码里。Vim 继承了下来，一直传到今天。

**实际手感**：现在，把你的右手食指放在 `J` 键上。摸到了吗？那个键上有个小凸起，是所有键盘用来帮你定位的“锚点”。食指找到这个凸起后，你的手指会自然覆盖在 `H`、`J`、`K`、`L` 四个键上——向右是 `L`，向左是 `H`，向下是 `J`，向上是 `K`。这就是 Vim 的核心移动区，也是你接下来几节课要反复练习的“家”。

**小结**：你用 `hjkl` 移动光标，不是因为这样最科学，是因为 1976 年那台机器的键帽上就是这么印的。四十年后，这个“偶然”成了所有 Vim 用户的肌肉记忆。

---

#### 1.4 什么是终端？

Vim 运行在 **终端** 里。

终端是一个“能打字跟电脑说话的黑框框”。不同系统的叫法不同：

- Windows：命令提示符 或 PowerShell
- Mac：终端
- Linux：终端

> 如果你没用过终端，没关系。你现在只需要知道：Vim 住在里面。打开终端，输入 `vim`，就能启动。

**小结**：终端是 Vim 的“家”。先打开终端，再启动 Vim。

---

#### 1.5 安装 Vim

**不知道你的电脑是什么系统？**

- 左下角有“开始”菜单 → Windows
- 左上角有苹果图标 → Mac
- 不知道 → 大概率是 Windows

根据你的系统，选一个方法。

---

##### 1.5.1 Windows 用户

Windows 本身没有 Vim。需要先安装 **WSL**（Windows 上的 Linux 子系统）。

> 别被名字吓到。你可以把 WSL 理解成“Windows 电脑里的另一台小电脑”，专门用来跑 Linux 程序。装一次就行。

步骤：

1. 打开“开始”菜单，搜 `PowerShell`
2. **右键点击“PowerShell”，选择“以管理员身份运行”**（这一步很重要）
3. 在黑框框里输入下面这行命令，按回车：

   ```bash
   wsl --install
   ```

4. 等几分钟，**重启电脑**
5. 重启后，打开“开始”菜单，搜 `Ubuntu` 并打开
6. 第一次打开要等一会儿，然后让你输入**用户名和密码**。随便写（比如 `vimer`），别忘
7. 在 Ubuntu 里输入下面这行命令，按回车：

   ```bash
   sudo apt install vim -y
   ```

   输入密码时屏幕上不显示任何字符，正常输入就行

---

##### 1.5.2 Mac 用户

Mac 自带老版的 `vi`，需要装新版的 Vim。

1. 打开“启动台”→“其他”→**“终端”**
2. 先装 Homebrew（Mac 的软件管家）。在终端里粘贴下面这行命令，按回车：

   ```bash
   /bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)"
   ```

   等几分钟，中间可能让你按回车确认
3. 装完后，在终端里输入：

   ```bash
   brew install vim
   ```

---

##### 1.5.3 Linux 用户

打开终端（快捷键通常是 `Ctrl+Alt+T`），输入：

```bash
sudo apt install vim -y
```

如果提示 `command not found`，把 `apt` 换成 `yum` 或 `pacman`。

**小结**：按自己系统的步骤来，一步一步敲命令。装不上就去搜报错信息。

---

#### 1.6 验证安装

安装完成后，在终端里输入：

```bash
vim --version
```

按回车。

如果屏幕上出现一大堆以 `VIM` 开头的信息，中间有 `Huge version` 之类的字眼——**Vim 安装成功**。

如果提示 `command not found`，说明没装上。检查哪一步命令打错了，或者关掉终端重新打开再试一次。

**小结**：`vim --version` 是验证命令。看到 `VIM` 就对了。

#### 1.7 第一次启动

在终端里输入 `vim`，按回车。

画面变了。屏幕上有版本号、帮助提示，底下有一行状态条。

**你现在在 Vim 的“普通模式”下。**

试试按一下字母 `i`，你会发现——你能打字了。按 `i` 进入了“插入模式”。

现在不需要搞懂模式是什么。你只需要知道：**你怎么退出去？**

**活着退出去的方法（这是 Vim 最重要的操作）**  

1. 按 **`ESC`** 键（键盘左上角）
2. 输入冒号 **`:`**（左下角会出现冒号）
3. 输入 **`q!`**（左下角变成 `:q!`）
4. 按 **回车**

屏幕闪了一下，你回到了终端。

> `q!` 的含义：
>
> - `:` 进入命令行模式
> - `q` 是 quit（退出）
> - `!` 是强制。你没保存任何内容，不加 `!` Vim 会拦着你，加了这个就是告诉它：我知道没保存，退！

**小结**：`ESC` → `:` → `q!` → 回车。这四个动作是你的“救命稻草”。记不住这四步，别的都不需要学。

## 第二部分：通往专家之路（选修）

> **目标**：让你从“会用”变成“精通”。  
> **这部分内容来自《Vim 实用技巧》的深度解读。**  
> 读完前十课后，根据你的痛点，挑着读：

### 我应该从哪个选修开始？

| 如果你遇到这些情况 | 去读 |
| :--- | :--- |
| 每次都要按好几下才能删掉引号里的内容 | **选修 1：文本对象** |
| 复制粘贴总被覆盖，烦死了 | **选修 2：寄存器** |
| 重复操作太多，手指都麻了 | **选修 3：宏** |
| 不想背命令，想自己“推导”出来 | **选修 4：Vim 是一门语言** |
| 想让 Vim 变成你喜欢的样子 | **选修 5：配置 `.vimrc`** |
| 想让 Vim 变成 IDE | **选修 6：插件生态** |

### 选修 1：文本对象 —— 操作的单位升级了

- 什么是文本对象？（`iw`、`ip`、`i"`、`i(`……）
- 操作符 + 文本对象：`dip` 删除一个段落，`ci"` 删除引号内内容并进入插入模式
- 实战：批量修改 HTML 标签属性

### 选修 2：寄存器 —— VIM 的“多个剪贴板”

- 什么是寄存器？
- 默认寄存器（`""`）、复制专用寄存器（`"0`）、命名寄存器（`"a`-`"z`）
- 实战：同时操作多段文本，互不干扰

### 选修 3：宏 —— 录制操作，一键重放

- 录制宏：`q` + 寄存器名
- 播放宏：`@` + 寄存器名
- 实战：在 100 行代码前面都加上 `//` 注释

### 选修 4：VIM 是一门语言 —— 命令组合的逻辑

- 操作符 + 动作命令：`d` `c` `y` 是动词，`w` `$` `f` 是名词
- 为什么 Vim 不需要背太多命令？（因为学会组合 = 学会新命令）
- 实战：从“按命令”到“想命令”的思维转变

### 选修 5：配置 `.vimrc` —— 让 VIM 变成你的形状

- `.vimrc` 是什么？放哪？
- 基础配置：行号、语法高亮、缩进、主题
- 守夜者推荐配置模板（直接复制可用）

### 选修 6：插件生态 —— 把 VIM 变成 IDE

- 插件管理器：vim-plug（最轻量）
- 必装插件：NERDTree（文件树）、coc.nvim（补全）、fzf（模糊搜索）
- 守夜者提醒：插件不是越多越好，够用就行

### 附录 D：常见坑与解法（新手救急）

| 现象 | 原因 | 解法 |
| :--- | :--- | :--- |
| 按 `i` 没反应，打不出字 | 你不在普通模式 | 按 `Esc` 再试 |
| 按 `h` `j` `k` `l` 变成了输入字母 | 你在插入模式 | 按 `Esc` 退出 |
| `:wq` 报错 `E212: Can't open file for writing` | 没有写权限 | `:w !sudo tee %`（或用 `sudo` 重新打开） |
| 打开文件全是乱码 | 编码问题 | `:e ++enc=utf-8` |
| 按 `Ctrl+s` 卡死了 | 你按了 XOFF 流控制 | `Ctrl+q` 解除 |
| 不小心按了 `Ctrl+z`，Vim 不见了 | 被挂起到后台 | `fg` 回到 Vim |
| 撤销撤多了，想“反撤销” | 不知道 `Ctrl+r` | `Ctrl+r` 重做 |
